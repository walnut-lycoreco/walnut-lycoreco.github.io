這題有兩種解法！

解 1

傳入一個夠小的浮點數，會被 JavaScript 解析為 1，但是會被 SQLite 解析為 0 的

解 2

這是隊友使用的做法：

  const cartEntries = productsToAdd.map((prod) => ({ ...prod, username: res.locals.username }));
  await db`INSERT INTO cart_items ${db(cartEntries)}`;

這邊的 ${db(cartEntries)} 在 JS 內部其實會抓取 Index 0 的物件下的屬性作為 Columns 插入資料庫
所以如果 Index 0 的物件不要設定 is_sample，那會因為是 NULL 而變成 0，接著 Index 1 放入 FLAG 並且把 is_sample 設為 1，可以通過 JavaScript 但在 SQLite 裡面一樣是空！
最後結帳就可以拿到 FLAG 了

    "products": [
        {"book_id": CHEAP_BOOK_ID},
        {"book_id": FLAG_BOOK_ID, "is_sample": 1},
    ]

ad-note

這是一道 XSLeak 的題目，網站可以新增廣告並且是把內容 iframe 進去，目的是要偷到某一篇 POST 的內容 (nonce) 並且回到 /flag 取得 FLAG
另外還有提供一個搜尋功能，它會將 POST 和廣告內容混合查詢

這一題的梗有兩個：

  1. 瀏覽器 fetchLater 行為 這個函數允許在關閉頁面後持續抓取資料，而 nonce 頁面內容小於其他廣告。
    同時，fetchLater 是有記憶體分配大小的，一個頁面最多 512 KB，配合此時有 8 個 iframge 所以每個 iframge 只有 64 KB，回到 nonce 頁面內容小於其他廣告，可以透過這個 API 做剩餘記憶體大小試探！

  2. 它有一段 JS

setReferrerPolicy(iframe) {
    const params = new URLSearchParams(window.location.search);
    const policy = params.get('referrerPolicy');
    const propName = Array.from(params.keys())[0];
    const trustedValue = trustedPolicy.createHTML(policy);
    
    iframe.setAttribute(propName, trustedValue); 
    return iframe;
}

這邊可以進行屬性汙染，當傳入的 url 像是 ?allow=foo&referrerPolicy=deferred-fetch 時，可以 將 allow 屬性設定為 deferred-fetch 並建立一個新的 iframe！這樣才可以使用像是 fetchLater 這類高消耗/實驗性質的 API

extend-note

又是 XSLeak，我發現前端安全真的好難 ＞﹏＜

  1. 有網址 Redirect 行為，不過被 python urllib 解析 host 要跟題目靶機 host 一樣
  2. 要想辦法跨站偵測 404 行為

梗：

  1. python urllib 對於 0w0-b.com\@ctf.com 的 host 解析會是 ctf.com，不過對於瀏覽器而言是在 0w0-b.com 開啟路徑 /@ctf.com
  2. 瀏覽器有 BfCache 機制可以進行 history.back，但是 404 會中斷 Cache 鍊，可以多重新導向幾次來穩定 Cache
